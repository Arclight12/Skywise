## 2025-10-24 - Missing Input Validation & Secure Error Handling in Core Data Model
**Vulnerability:** The core data model (`DataNode` in `satellite_prioritization_code/core/datamodel.py`) accepted raw CSV inputs without validating bounds (e.g. `quality` must be between 0 and 1) or types. Simultaneously, the main application script (`satellite_prioritization_code/main.py`) lacked top-level error handling, meaning that invalid data during instantiation could lead to raw stack traces being output to the user.
**Learning:** In data processing pipelines, raw data ingestion often lacks standard web-framework validations. Without sanitization and safe bounds at the model instantiation level, corrupted or adversarial data can crash the application and leak internal state information via tracebacks.
**Prevention:** Implement strict type and bounds validation at the lowest data model level. Additionally, wrap primary execution points in secure `try...except` blocks that return generic error messages instead of leaking internal exceptions.
